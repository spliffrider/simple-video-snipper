# Simple Video Snipper macOS build plan

Build a native macOS menu bar app with the same capture, save, and share flow as the [Windows version](../README.md). Use Swift, SwiftUI, and AppKit under `macos/` in this repository. Start with a macOS 15 minimum deployment target and Xcode 16 or newer. Use a stable bundle identifier throughout development so macOS can associate capture permissions with the app. [Apple’s ScreenCaptureKit sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)

## Start from Codex on the Mac

Clone this repository or pull the latest `main` with your GitHub account, then work on a Mac-specific branch under `macos/`. Check Xcode and the macOS SDK first. Build an area-to-MP4 spike that records a local color grid, decode the four corners, and exercise Stop before building the full menu bar UI. Use the Windows implementation to match behavior and defaults. The [Windows README](../README.md#save-and-share-recordings) describes the shared save experience, and the [Windows export workflow](../Export/SaveWorkflow.cs) shows the retry and recovery actions. The Windows installer is the next Windows milestone.

## Build the first working recorder

1. Create a SwiftUI `MenuBarExtra` with **Record Area**, **Record Window**, **Record Chrome Tab**, **Stop**, and **Settings**. Use a system-wide shortcut through the KeyboardShortcuts Swift package. Start with configurable `⌃⌥⇧R`. A shortcut pressed during capture brings the recording controls forward. Keep a menu action available when the shortcut is unavailable. [KeyboardShortcuts package](https://github.com/sindresorhus/KeyboardShortcuts)
2. Build a borderless AppKit area-selection panel for the display under the pointer. Store the drag bounds relative to that display, normalize drags in either direction, and allow resizing and Esc. Match `NSScreen` to `SCDisplay` using `CGDirectDisplayID`. Convert AppKit’s bottom-left coordinates to the display-local top-left source rectangle. Use the filter’s `pointPixelScale` when setting the encoded pixel dimensions. Snap to even dimensions consistently in the outline and encoder. Exclude the app’s controls from the display filter. [Screen capture sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) · [Source rectangle](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/sourcerect) · [Point-to-pixel scale](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/pointpixelscale)
3. Use `SCContentSharingPicker` for a single window or list eligible `SCWindow` objects from `SCShareableContent`. A selected window uses `SCContentFilter(desktopIndependentWindow:)`. Record at 30 fps with fixed output dimensions. Fit resized content into the original dimensions while preserving aspect ratio. If the source closes, stop and finalize the frames already captured. [ScreenCaptureKit](https://developer.apple.com/documentation/ScreenCaptureKit)
4. Try `SCRecordingOutput` with MP4 and H.264 for the first playable clip. Check the available output types and codecs and wait for the recording delegate to report that the file finished. Decode a grid recording at two actual point-to-pixel scales before adding more controls. [ScreenCaptureKit recording APIs](https://developer.apple.com/documentation/Updates/ScreenCaptureKit)

## Add independent audio

Keep **Microphone** and **System audio** off by default. Use ScreenCaptureKit’s `capturesAudio` and `captureMicrophone` options independently, `microphoneCaptureDeviceID` for the selected input, and `excludesCurrentProcessAudio` for the app’s own sounds. Add a mic meter before recording. Check the resulting MP4 for both signals in ordinary playback. If the direct recording output does not provide the desired mix, use the ScreenCaptureKit `.audio` and `.microphone` sample callbacks with AVFoundation. Convert both sources to a common PCM format, align their presentation timestamps with video, and write one AAC mix using `AVAssetWriter`. On mic loss, continue video and any remaining audio and show which input was lost. [Apple’s audio capture walkthrough](https://developer.apple.com/videos/play/wwdc2024/10088/) · [AVAssetWriter](https://developer.apple.com/documentation/avfoundation/avassetwriter)

Use the macOS screen recording permission flow. Request mic access when the mic option is enabled. Include `NSMicrophoneUsageDescription` and the applicable screen/system-audio usage descriptions in the target. Handle denial with a message in the app and test first launch with a fresh permission state. [ScreenCaptureKit permissions](https://developer.apple.com/documentation/screencapturekit?changes=_5__8) · [Microphone authorization](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos) · [System audio usage description](https://developer.apple.com/documentation/bundleresources/information-property-list/nsaudiocaptureusagedescription)

## Reuse the Chrome companion

Serve the existing [Companion files](../Companion/) on an ephemeral loopback port. Read [the Windows recording host](../RecordingHost.cs) for the contract. The browser opens a session-scoped WebSocket, receives `ready`, sends binary WebM chunks in order, and sends `finish` after the final chunk. The desktop app can send `stop`. After finalizing the staged copy, reply `staged:<title>` and send the clip through the same save flow as native recordings. On a capture failure, reply with `error:<message>`. Match the incoming Origin to the local page, use an unpredictable session path, and accept one recording at a time. The browser permission picker selects the actual tab. Open Chrome explicitly from the menu bar and verify that switching tabs leaves the recording on the selected tab. [Chrome source picker](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)

## Save, share, and package

On first launch, ask the user to confirm a temporary recordings folder. Prefill `~/Library/Application Support/Simple Video Snipper/Recordings`. Use `NSOpenPanel` to choose a different writable local directory. Verify that the app can create, write, and delete a probe file and expose the setting under **Settings → Storage**.

Write captures to an app-owned staging file and preserve it if export fails. Use `NSSavePanel` for **Ask every time**. **Quick Save** uses the preferred folder and a unique filename. Take MP4 (H.264/AAC) as the default export and offer WebM (VP9/Opus) through a shared exporter once the native path is stable. For **Copy video file**, write the completed file URL to `NSPasteboard.general`. Auto-copy defaults off. Offer **Show in Finder** after saving. Sign and notarize the distributable app for direct installation. [Pasteboard file URLs](https://developer.apple.com/documentation/appkit/nsurlpboardtype) · [Apple notarization guide](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

## Acceptance checks on the Mac

- Run a complete shortcut → drag → Record → Stop → save pass while another app is active. Decode a colored pixel grid on at least two configurations with different measured point-to-pixel scales. Test reverse drags and a display placed to the left of the primary display.
- Resize the selected window while recording and close it to stop. Confirm that the MP4 plays, the output dimensions stay fixed, and the window content fits without stretching.
- Play a generated tone and tap near the mic in three recordings. Verify mic-only, system-only, and mixed audio by decoding the saved files. Check audio/video sync over a multi-minute clip and verify that unplugging the selected mic preserves the other source.
- Record a Chrome tab with sound, switch tabs, and stop both from Chrome and from the menu bar in separate runs. Confirm the desktop app saves a playable file each time.
- Try invalid staging and export paths, retry a failed export, and paste a copied clip into Finder. Install a signed build in a fresh macOS account and repeat the setup and capture flow.
